# Detection & Fix Patterns（问题诊断与修复模式）

遇到异常行为时先查阅本表。每个条目：问题 → 症状 → 修复。

| Problem | Symptom | Fix |
|---|---|---|
| No ground plane | High EMI | Add continuous GND pour |
| Missing decoupling | Noise on rail | 100nF + 10uF per IC |
| Clock too close to edge | EMI fail | Move ≥3× trace width from edge |
| Capacitor too close to CPU | Poor transient | Place within 500mil of power pin |
| Via too small | High resistance | Use 0.3mm min via |
| No ESD protection | Field failures | Add TVS to external connectors |
| IC supply voltage exceeded (most destructive error) | IC runs hot / smoke / no output on power-up. CMOS op-amp (Vmax=5.5V) from Boost 9.5V — SPICE behavioral models have no VCC pins so simulation passes | **SPICE 不能替代供电电压审查。** 行为模型不检查 VCC，仿真通过不意味着设计安全。必须在 Phase 2 §2.1 选型阶段执行电压审查，Phase 5a 复查。详见 Phase 3 `⚠️ SPICE Behavioral Model 核心约束`。修法：从较低电压轨取电、加 LDO 降压、或换更高耐压的替代型号（如 TLV2371→TLV2171 16V ✅）。 |
| Missing reverse polarity protection | Board works if plugged correctly; first reverse-plug kills everything | Add Schottky diode (SS12/SOD-123, GND→Vin) on every board with external power input |
| Missing ESD caps on external IO | Works in lab; random lockups/ drift in field | Add 100pF NP0 to GND on every external connector line (VIN, TTL, ANA). Place within 5mm of connector. |
| Dense board DRC violations misinterpreted | 200-300 clearance/silk/courtyard violations reported, leading to worry about "bad design" | **In <25mm boards with 20+ components, only count functional errors** (shorting_items=0, unconnected_items<10). clearance/silk/courtyard are physically unavoidable at this density and can be ignored. Design rule violations ≠ board won't work. |
| Inline symbols in schematic not rendering in KiCad 10 | Symbols show as empty text boxes with no graphical shape | 使用封装库的符号代替内联符号。避免在 `<kicad_sch>` 中使用纯 `(lib_symbols (symbol "R" ...))` 内联定义方式——KiCad 10 不渲染这些内联图形。替代方案：生成简版 .kicad_pro 项目，用符号编辑器占位，再输出 SVG 原理图给文档。 |
| Schematic inline symbols broken after KiCad 7->10 migration | 原理图只有文字标注没有图形 | 手动重新放置符号（不推荐）或仅用 PCB 文件 + SVG 预览图替代原理图图形验证。设计报告中的电路图用文字/ASCII 图描述，不用依赖 KiCad 渲染。 |
| SPICE simulation runs but outputs no data | output.txt 包含 "No .plot, .print, or .fourier lines; no simulations run" | 网表缺少 `.PRINT` 指令—— `.AC` / `.TRAN` 分析本身不产生可打印输出。添加 `.PRINT AC VDB(output) VP(output)` 后重新运行。**注意**：`.PRINT` 后面必须跟分析类型关键字（`AC`/`TRAN`/`DC`），否则 ngspice 仍可能忽略它。 |
| SPICE `limit()` function broken in ngspice-42 | B-source 中 `V=limit(x,lo,hi)` 或 E-source `VALUE {limit(…)}` 返回 NaN/错误。`if()` 函数也在部分上下文中不可用。 | **ngspice-42 回归 bug**（2026-06-05 实测，PPS 42+ds-3build1）。使用 `min(max())` 替代：`V=min(hi, max(lo, x))` 等价于 `limit(x, lo, hi)`。注意参数顺序不同：`limit(x, lo, hi)` → `min(max(x, lo), hi)`。`min()` 和 `max()` 在 B-source 和 E-source 中均正常工作。详见 `references/ngspice42-limit-bug.md`。 |
| KiCad first-run wizard blocks GUI on fresh WSL install | pcbnew board.kicad_pcb opens KiCad Setup welcome dialog that blocks board loading. No components/tracks/zones appear in editor despite valid file. | Set first_run_shown true in ~/.config/kicad/10.0/*.json. sed before launching. Automated in Phase 0. |
| kicad-cli pcb drc CLI DRC works | Assumed CLI has no DRC but kicad-cli pcb drc exists. | Use kicad-cli pcb drc board.kicad_pcb -o report.rpt --all-track-errors --units mm --exit-code-violations. Supports severity-error/warning/all. Formats: report, json. Handles refill-zones and save-board. |
| KiCad 10 EDA_ANGLE rotation API | from pcbnew import FromDegrees ImportError | KiCad 10 FromDegrees does not exist. Use EDA_ANGLE(degrees, 1) or ANGLE_90/ANGLE_45 constants. Example: fp.SetOrientation(ANGLE_90). |
| SOT-23-3 transistor pin assignment wrong (most common PCB layout error) | MOSFET operates in wrong region (inverted conduction, VGS lower than expected), BJT won't turn on or collector/emitter swapped. Body diode forward-biased → current flows through diode even when Vgs=0 → load never turns off. | Every SOT-23-3 transistor insertion must pass Phase 5a pin assignment check. KiCad SOT-23-3 pad numbering (1=bottom-left, 2=top-left, 3=right-center) MUST be cross-referenced with device datasheet pinout. **After assigning nets, trace the signal chain end-to-end for every transistor** — don't just check pad numbers; verify the full path: op-amp OUT → Gate → Source → sense resistor. This catches swaps that pad-number checks miss. |
| MOSFET Source/Drain swapped | Body diode forward-biased → load current flows even at Vgs=0 → load never turns off. Checking pad numbers alone doesn't catch this because both source and drain nets exist; the symptom is the load staying on during control OFF. | Trace the signal chain end-to-end for each transistor: Gate (signal source) → Source (sense resistor/GND) → Drain (load). Verify body diode direction: for N-channel with Source→GND/VSNS and Drain→load, the body diode is reverse-biased ✅. If Source goes to the load and Drain to GND, the body diode is forward-biased ❌. |
| Dense board GND copper pour errors | solder_mask_bridge / shorting_items 大量报错 | 在 <20mm 密布局板上（22+元件），全板 GND 覆铜会导致大量冲突。改用 0.5mm 厚 GND 走线构建总线，或设 clearance ≥ 0.3mm。 |
| Dense board DRC violations >200 | DRC 报告显示 200-300 条违规（clearance/silk/courtyard），无 short/unconnected | **在 19.8×23.8mm 板、22 元件、92 走线的密布局上是正常的**（2026-06-05 三次实测：262 违规，均为 clearance/silk/courtyard，0 short，4 unconnected）。判断标准只看 functional 类（shorting_items=0, unconnected_items ≤ 少数因微小偏移导致的未连接）。clearance/silk/courtyard 在密布局板上可忽略，受物理约束限制不可能降到 0。DRC 放行条件：shorting_items = 0，unconnected_items < 10。 |
| kicad-cli thought available only for export | assumed kicad-cli only exports Gerber/SVG, not DRC/render/stats/pos | **KiCad 10 kicad-cli 支持完整的子命令集**：`pcb drc`（DRC检查）、`pcb render`（3D渲染）、`pcb export stats`（统计报告）、`pcb export pos`（贴片坐标）、`pcb export gerbers`（Gerber）、`pcb export drill`（钻孔）、`pcb export glb`（3D模型）、`pcb export svg/pdf`（可视化）、`sch export svg`（原理图）、`project new`（创建项目）。使用前先 `kicad-cli pcb --help` 和 `kicad-cli pcb export --help` 查看所有可用子命令，不要假设只有你知道的那几个。 |
| WSL SVG→PNG believed broken | 认为 cairosvg/rsvg-convert 在 WSL 上不可用 | **实测正常**（KiCad 10.0.3 + Ubuntu 24.04 WSL）。cairosvg 2.9.0 和 rsvg-convert 2.58.0 均能正确渲染 KiCad SVG。 |
| PyMuPDF renders KiCad PDF as garbled | PDF 转 PNG 后图片破碎、文字错位 | WSL 的 PyMuPDF 可能无法正确渲染 KiCad PDF。改用 Windows 端转换或直接使用 SVG |
| PCB pad net assignments reversed | 信号流向错误（VIN 走到输出端） | pcbnew 的 `list(fp.Pads())` 在 KiCad 10 中**已按焊盘编号排序**（2026-06-05 实测），但为安全起见仍用焊盘编号 `pad.GetNumber()` 分配网络。 |
| KiCad 10 PLOT_CONTROLLER API differs from KiCad 7 | `OpenLayer()` 不存在；`SetLineWidth()` 不存在 | KiCad 10 的 PLOT_CONTROLLER 使用不同 API。优先用 kicad-cli 导出（`pcb export svg`），不要用 pcbnew Python 脚本控制绘图。 |
| D: drive file lock when saving DOCX | PermissionError: [Errno 13] | WSL 写 D: 盘时，Windows 的 wps.exe/WINWORD.EXE 可能持有文件锁。先 taskkill 再 copy：`subprocess.run(['taskkill.exe','/F','/IM','wps.exe'])` + `shutil.copy2(tmp, target_path)` |
| pcbnew PAD drill fails with AttributeError | `pad.SetDrill(mm(x))` raises `AttributeError` | KiCad 7 中使用 `SetDrillSize(pcbnew.VECTOR2I(mm(d), mm(d)))` 代替 |
| Agent claims "xdotool can't send any events on WSLg" | User corrects: "胡说八道，这个你完全能做到" — because mouse clicks DO work. The agent made a blanket statement without reading `references/kicad-gui-automation-wslg.md` first. | **Read the reference file BEFORE making WSLg xdotool claims.** The file documents exactly what works (mouse clicks ✅, toolbarmenu clicks ✅) and what doesn't (keyboard shortcuts ❌). A blanket "xdotool doesn't work" is wrong and wastes user trust. Primary automation path: pcbnew API / kicad-cli. GUI automation via mouse clicks = fallback for operations without CLI equivalent. |
| pcbnew zone creation segfaults | Creating copper pour via ZONE() + Append() causes segmentation fault | KiCad 7 zone API 不稳定。稳妥方案：直接写 S-expression，不在 pcbnew API 中创建铜皮。也可在 KiCad GUI 中一键填充（选中区域按 B）。 |
| pcbnew Reference/Value 丝印文字在 board.Add() 后丢失 | SetPosition() 设了丝印位置，但实际在焊盘正中间叠着 | **board.Add(fp) 之后** 再设文字，用板绝对坐标。KiCad 10 中 footprint 只有属于 board 后才能正确解析坐标。见 Phase 5 详细代码示例。 |
| KiCad 10 net assignment in pcbnew doesn't serialize to disk | After `SetNet()`, the file on disk shows the pad has no net. Net exists in memory but `.kicad_pcb` S-expression is missing the net assignment. | Call `p.SetPosition(p.GetPosition())` after every `SetNet()` call. This forces pcbnew to re-compute the pad's position metadata, which triggers net serialization into the S-expression tree. Without this, all net assignments are silently dropped on `board.Save()`. |
| Dense board routing order | Starting routing without a strategy leads to DRC unconnected_items and rework. | Route in this order: (1) **Power nets first** (VIN, VOUT) with 0.4-0.5mm width — these are the most constrained by component positions. (2) **Critical signal nets** (GATE, FB) with 0.3mm — high-speed/feedback paths need shortest routes. (3) **GND bus** with 0.5mm thick traces connecting all remaining pads. On boards <25mm with 20+ components, skip copper pour entirely and use 0.5mm GND bus traces — full-board GND pour produces hundreds of solder_mask_bridge violations. |
| pcbnew BOARD.GetFileFormatVersion() missing in KiCad 10 | AttributeError: 'BOARD' object has no attribute 'GetFileFormatVersion' | KiCad 10 中该方法已重命名为 `GetFileFormatVersionAtLoad()`。替代检查方式：`python3 -c "import pcbnew; board = pcbnew.BOARD(); print('pcbnew OK:', board.GetFileFormatVersionAtLoad())"`。 |
| PAD() requires FOOTPRINT parent in KiCad 10 | TypeError: new_PAD() 'Wrong number or type of arguments'. `PAD()` without args was valid in KiCad 7. | KiCad 10 中 `PAD()` 必须传父 FOOTPRINT 对象：`pad = PAD(fp)`。不能用 `PAD()` 创建后再 `fp.Add(pad)` — 正确顺序是 `pad = PAD(fp)` → 配置属性 → `fp.Add(pad)`。 |
| LSET does not support `|` operator in KiCad 10 | TypeError: unsupported operand type(s) for |: 'LSET' and 'LSET' | KiCad 10 的 LSET 不支持位操作符。用 `AddLayerSet()` 合并：`mask = pcbnew.LSET.AllCuMask(); mask.AddLayerSet(pcbnew.LSET.AllTechMask())`。预置工厂方法：`FrontMask()`(顶层铜+阻焊)、`AllCuMask()`(所有铜层)、`AllTechMask()`(所有技术层)。 |
| pcbnew.PCB_LAYER_ID class removed in KiCad 10 | ImportError: cannot import name 'PCB_LAYER_ID' from 'pcbnew' | KiCad 10 中层 ID 是直接 int 常量，无 PCB_LAYER_ID 包装类。用 `pcbnew.F_Cu`(0)、`pcbnew.B_Cu`(2)、`pcbnew.Edge_Cuts`(25)、`pcbnew.F_SilkS`(5)。完整对照表见 `references/kicad7-pcbnew-api.md` > KiCad 10 差异章节。 |
| GLB export crash with --board-only (old KiCad 10 builds) | "double free or corruption (fasttop)" abort | **2026-06-05 实测**：KiCad 10.0.3 上 `--board-only` 正常，不崩溃。如果旧版本遇到问题，移除 `--board-only` 并增加 `--include-tracks --include-pads` 可规避。 |
| sexpdata.dumps output unreadable by KiCad | "Unknown token 'kicad_pcb'" error | sexpdata.dumps() 给所有符号加引号变成 ("kicad_pcb")，KiCad 不认。必须用原始字符串直接写 S-expression。 |
| Agent told user to operate KiCad GUI manually | "你打开KiCad按F7" / "你在GUI里调整丝印" / "你运行DRC" — 用户明确拒绝任何手动操作 | **交付物必须开箱可用。** `kicad-cli pcb drc` 能做DRC就别让用户按F7；`kicad-cli pcb export gerbers` 能做Gerber导出就别让用户点菜单。所有能让电脑自动完成的操作都必须自动完成。用户说"不许给我布置任务"意味着你的交付物每一行都必须能直接在终端/CLI验证，不需要人工介入。 |
| SPICE diode model overflow at high Vf | Simulation fails with singular matrix, V(VSNS) stays at numerical noise (~10^-200). Diode model with IS=1e-15 N=1 at >5V forward bias overflows. | Add `RS` to diode model (e.g. `RS=20`). Or substitute LD with equivalent resistor `R = Vf/I` during simulation. See `references/spice-simulation-pitfalls.md`. |
| SPICE MOSFET won't conduct | VGS > VTO but Id ≈ 0. Cause: W/L too small for required current. | Increase W. Calculate: `Id=0.5*KP*(W/L)*(VGS-VTO)^2`. For 200mA: W=10000u, L=1u. Same reference file. |
| SPICE transient oscillation in closed loop | Op-amp B-source/VCVS model with gain>1000 causes hard switching when feedback crosses zero. | Reduce gain to 100, add compensation (R=10k/C=100p). Or use open-loop verification: DC sweep gate, then fix gate bias and test modulation separately. |
| SPICE high-gain op-amp + MOSFET feedback fails to converge | Behavioral G-source/VCVS models with gain >> 1000 in closed-loop constant-current feedback produce singular matrix / NaN with MOSFET models. Multi-stage (op-amp → MOSFET → sense) gain chain amplifies numerical noise. | (1) Test the core loop with an ideal current source first. (2) Reduce op-amp gain to 100-1000 for transient analysis. (3) Add Rpole+Cpole compensation (~1us time constant). (4) If still fails, validate with DC sweep analysis instead of TRAN, then use datasheet GBW spec as bandwidth guarantee. |
| SPICE E-source min(max()) fails in transient (segfault/timestep too small) | E-source with `VALUE {min(hi, max(lo, V(...)))}` works in DC analysis but aborts transient with "Timestep too small; trouble with node" at the clamping boundary. The min()/max() creates a derivative discontinuity at the clamp point that the transient solver cannot cross. | **Use DC sweep for CCS verification instead** — `.DC` analysis handles min(max()) cleanly because it doesn't compute time derivatives. For transient verification of TTL on/off: sweep TTL from 0V to 5V in 2 steps with `.DC` and observe both states. The DC operating points at TTL=0 (ON) and TTL=5 (OFF) are equally valid proofs of circuit function. Only fall back to transient if you need switching speed or overshoot data, and in that case use a simpler model (gain=100 without rail clamping). |
| **审计自指循环陷阱** — 审计脚本期望值来自被审代码自身 | 晶体管引脚检查显示"全部 ✅"，但实际晶体管源/漏完全接反。审计脚本的期望值 not 来自数据手册，而是来自被审代码的拼写。检查的不是"晶体管接对了没"而是"代码和注释一致不一致" | **C.3a 预期值独立性规则**：审计脚本的每个期望值必须标注来源（"来自晶体管 datasheet §Pin Configuration: 1=Gate,2=Source,3=Drain"）。不能从被审代码、注释、变量名反推期望值。见 Phase 5a 6号审查模式。 |
| Programmatic 3D rendering vs kicad-cli render | Used trimesh+matplotlib to render GLB → PNG 3D preview. Also attempted GLB+trimesh for `--board-only` renders that trimesh handled poorly (missing components). | **首选用 `kicad-cli pcb render board.kicad_pcb --output render.png --side top --quality high`**。KiCad 原生光线追踪渲染器（PNG/JPEG 输出），支持 top/bottom/left/right/front/back 视角和 basic/high 质量。**比 kicad-cli export glb + trimesh 方案快 10 倍且效果更好。** GLB+trimesh 只在需要自定义视角/标注时使用（如配合 matplotlib 添加元件标签）。 |
| SPICE first line eats your component | Simulation runs with no warnings but V(VREF)=0 even though you set DC 1.5. The component on line 1 was silently consumed as a TITLE line. | Add `* description` or empty line as the first line of every `.cir` file. Never put a component definition on line 1. |
| SPICE AC analysis runs but all gain values are 0.000000e+00 | 400+ data rows, no warnings, but VDB(x)=0 everywhere. Cause: VCVS output saturated at external rail (e.g. 150kV), making small-signal AC gain ≈ 0. | Don't add MIN/MAX limits to VCVS (same problem on the clip boundary). Use open-loop measurement instead: disconnect feedback, read GBW from open-loop Bode, derive closed-loop bandwidth mathematically. |
| KiCad genopa1 model won't converge in ngspice-42 | Closed-loop SPICE with genopa1 outputs clamped near VEE (~0V) regardless of input. DC .OP shows output rail is stuck. | genopa1 uses `Dlimit D N=0.01` diode clamp internally which conflicts with ngspice-42 solver (confirmed 2026-06-05). **Do not debug — proceed to alternatives**: (1) VCVS open-loop GBW measurement (<5% error from datasheet), (2) lower-gain VCVS + RC compensation, (3) vendor SPICE models from TI/ADI. See `references/spice-simulation-pitfalls.md` > KiCad genopa1 model section. |
| Silkscreen text judged "inside board" by center point only | 文字中心 r < 板半径 看着板内，但整段文字实际超边被铣掉（Ø14mm 板实测：21 字符 × 1.0mm 版本号，中心 r=6.52 而包围盒 r_max=12.21mm；v9/v10/v11 全部踩同一坑——只验证中心点）。TP 的 Reference/Value 字段默认在焊盘外侧 ~1.65mm，边缘测试点的 ref 直接落出板外 | **文字板内判据 = 包围盒 r_max，不是中心点**：`r_max = hypot(|x|+字宽/2, |y|+字高/2)`，字宽 ≈ 字符数 × 字号 × 0.62（KiCad 默认字体）。要求 r_max < 板半径 − 安全边距（Ø14mm 板取 6.9mm）。Ø14mm 板上 >10 字符 @≥1.0mm 的水平文字必然超边 → 拆两条（板号/版本分两行）、字号降 0.8mm、日期移出丝印。必须审计三类文字：板级 PCB_TEXT + 每个 footprint 的 Reference + Value 字段。完整流程（audit 脚本、修复手法、DRC 放行标准）见 **`pcb-silk-text-audit` skill**。 |

| 基准/参考电压从电源轨分压（2026-07-31 教训） | 设计点正常但输入电压偏离时恒流/输出严重漂移：520nmLD VREF 从 VIN 分压，VIN=12V → I_LD=191mA → **激光器过流损坏**（设计点 5V 时 79.7mA 一切正常） | **任何从电源轨分压的基准必须做电源偏离失效分析**：扫描 VIN 全范围（最低~最高+误接电压），量化对输出的影响；超出规格范围必须有警示标注（7b 表）+ 测试覆盖。分压型基准的电源敏感性是设计特性不是 bug——要么接受并标注，要么改从稳压轨取。 |
| 文档四方一致性（PCB↔BOM↔报告↔仿真网表） | 元件值在各文档间漂移：C1 在 BOM 写 10µF、PCB 实际 22µF，三轮审计才发现；仿真网表参数（v1.0 的 R7=3.3Ω）与设计不符导致报告不可信 | **每次 PCB 改动（值/封装/网络）必须四方同步**：①改 PCB ②同步 BOM ③同步设计报告 ④同步仿真网表并重跑。版本号统一（v2.2 级）。文档一致性检查（L.1）应核对 4 个数据源而非只看 BOM vs PCB。 |
