# 仿真模型保真度 — 避免模型抽象陷阱

## 问题

行为模型（如用 VCVS + RC 替代运放）能正确模拟小信号 AC 响应，但**完全没有器件级别的限定检查能力**（供电电压、输出轨限、输入共模范围等）。这会导致仿真"通过"但实际电路上电即烧。

## 本设计案例

TLV2371 用行为模型代替，仿真跑出完美 GBW=2.4MHz，完全没有提示 V+=9.5V > 5.5V。

## 规则

| 模型类型 | 能检测的错误 | 不能检测的错误 |
|:---------|:------------|:--------------|
| 裸 VCVS/RC | 带宽、增益 | 供电电压、输出轨限、功耗 |
| 带 VCC/VEE 子电路 | 供电电压、轨限 | 具体器件的 ABS MAX |
| 厂商 SPICE 模型 | 全部（包括工艺偏差） | — |

## 最佳实践

1. 首选厂商 SPICE 模型 — TI/ADI/Maxim 官网下载
2. 次选 KiCad 内置模型 — kicad_builtin_opamp 带 VCC/VEE
3. 自建模型必须带 VCC/VEE — 输出轨限随供电走，不硬编码
4. 开环仿真足够时不要硬套闭环 — 测 GBW 推带宽替代强行闭环
5. 仿真前跑 checklist 第 C 类（元件选型）— 先查额定值再仿真

## 兼容 ngspice-42 的工作模型

```
.SUBCKT OPAMP_VCC INP INN VCC VEE OUT
G1 0 1 INP INN 100u
R1 1 0 1e9
C1 1 0 6.63n
E1 2 0 1 0 100
B1 OUT 0 V=min(max(V(2), V(EE)+0.3), V(CC)-0.3)
.ENDS
```

limit() 在 ngspice-42 下损坏。始终用 min(max()) 替代。
